# 航标灯光巡检台

登记航标实测光强和方位偏差，服务端当场给出合格或不合格。页面由 Django 模板直接渲染，浏览器不另跑一套单页应用。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3190 |
| 应用 | http://localhost:8190 |
| PostgreSQL | localhost:54390 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| keeper | light123456 | 可登记 |
| watch | watch123456 | 只读 |

## 启动

```bash
cd projects/11-nav-aid-inspection
docker compose up --build
```

## 复测

不合格的记录可以另开一张复测单：原单留在总表不动，复测单记下所依原单的主键（`origin`），灯号与要求光强沿用原单，按本次实测光强和方位偏差重新判定。顶栏「复测链」把原单和后继复测串成链，从旧单指向新单；复测单也可再开复测，形成分支。

- 开复测入口：总表不合格行的「开复测」、不合格详情页的「开复测单」。
- 仅巡检员可开复测（GET 表单与直接 POST 均校验）；只读账号能看复测链，但没有任何开单入口。

## 验收

1. 打开 http://localhost:3190 ，用 keeper 登录，列表里 LH-01 合格、LH-09 不合格（偏暗种子）。
2. 再登记一条光强低于要求的记录，结论为光强不足。
3. 换 watch 登录，没有登记入口；直接提交登记会拒绝。
4. keeper 在 LH-09 上「开复测」，实测光强填 1400（补足灯光）、方位偏差 0.3，提交后复测单判定合格。
5. 回总表同时看得到新旧两张：LH-09 原单仍不合格，新行带「复测」标记并链接原单。
6. 顶栏「复测链」里，LH-09 原单经箭头走到新复测单；点编号可在原单与复测详情间互跳。
7. 换 watch 登录，能打开复测链并查看详情，但访问开复测页面（含直接 POST）返回 403，且不产生新单。
